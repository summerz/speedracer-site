# 드리프트 계약

기준: main 0.19.22 위 `feat/drift`. 물리·판정·보상 구현을 완료했고 아래 타입은 런타임 export다. Claude가 추진기 궤적·스파크·충전 표시를 연결한다. 앱 버전과 로드맵 완료 표시는 시각 연결 후 머지에서 처리한다.

## 조작과 진입

평소 자동 가속은 유지한다. 브레이크만 누르면 기존 감속이고, 코너 안쪽으로 브레이크와 조향을 함께 유지하면 드리프트한다. 별도 버튼을 추가하지 않는다.

| 입력 장치 | 드리프트 | 종료 |
| --- | --- | --- |
| 키보드 | S + A 또는 D, 코너 안쪽 방향 | S를 놓거나 조향을 중립/반대 방향으로 변경 |
| 터치 | 왼쪽 스틱을 아래 왼쪽/아래 오른쪽으로 밀기 | 아래 영역에서 벗어나거나 조향을 중립/반대 방향으로 변경 |
| 표준 게임패드 | LT + 왼쪽 스틱 좌우 | LT를 놓거나 조향을 중립/반대 방향으로 변경 |

기존 터치 정규화값을 사용한다. 브레이크 영역은 `y > 0.28`, 수평 데드존은 `0.12`다. 정규화 후 `abs(steer) >= 0.35`면 진입 조향으로 인정한다. 오른손 부스트·고도·각성 코어 배치는 그대로 사용한다.

진입 조건을 **0.15초 연속** 충족해야 한다.

- 레이스 진행 중이며 플레이어의 수동 주행이다.
- 브레이크를 누르고 `abs(steer) >= 0.35`다.
- 속도가 `max(20m/s, 일반 최고 속도 × 0.45)` 이상이다. 주행 보조의 속도 배율을 반영한 일반 최고 속도를 기준으로 한다.
- 트랙 프레임의 횡곡률 절댓값이 `0.0015m⁻¹` 이상이고 조향 방향과 곡률 부호가 같다. 수직 루프의 상하 굴곡이나 노면 롤 자체로는 진입하지 않는다.
- 부스트·각성·튜토리얼 자동 안내·점프의 공중 구간·분기 선택 입구/확정 후 인계 보정 구간이 아니다.

유지 조건은 `abs(steer) >= 0.20`, 횡곡률 `>= 0.001m⁻¹`로 낮춰 경계 떨림을 막는다. 속도 하한도 진입 하한의 80%로 낮춘다. 방향 반전은 즉시 종료한다. 연속 드리프트 재진입에는 0.25초와 브레이크 또는 조향의 해제가 필요하다. 직선에서 S+A/D를 흔들어 보상을 쌓을 수 없다.

## 미끄러짐 물리

현재 모델의 `heading`은 트랙 진행 방향에 대한 기체의 상대 진행 각도이며 `offset` 이동에도 사용된다. 드리프트도 이 좌표계와 기존 물리 거리 적분을 사용한다. 화면 모델만 돌려 미끄러지는 것처럼 보이게 하는 방식은 사용하지 않는다.

- 활성 중에는 기존 강한 브레이크 대신 속도 목표를 일반 최고 속도의 **78%**로 둔다. 목표보다 2m/s 이상 빠르면 기존 제동력의 18%로 감속하고, 2m/s 이상 느리면 일반 추력의 60%를 사용한다. 그 사이에는 별도 추력·제동 없이 기존 경사·코너·고도 저항을 적용한다. 내리막과 기체별 성능 차이는 유지한다.
- 일반 조향 yaw 용량의 **55%**, 중립 안정화 감쇠의 **60%**를 시작값으로 사용한다. 상대 진행 각도는 **±0.28rad(약 16°)**로 제한한다. 고정 각도를 강제로 부여하지 않고 기존 yaw 적분으로 미끄러짐을 만든다.
- `speed * cos(heading)` 전진 성분과 `speed * sin(heading)` 횡이동을 계속 계산한다. 드리프트 전용 순간 이동·중앙 고정·충돌 무시는 없다.
- 진입/정상 종료 때 계수는 0.15초에 걸쳐 바꾼다. 브레이크·조향 입력은 즉시 반영한다. S를 유지한 채 조향을 놓으면 기존 브레이크로 돌아가고, S를 놓으면 자동 가속으로 돌아간다.
- 기존 분기 선택/인계 보정이 우선한다. 드리프트는 해당 구간에서 시작하지 않고 진입 시 정상 종료한다. 경로 선택 경계와 입구 형상은 변경하지 않는다.

코너 폭과 기체별 응답을 검증해 위 계수를 조정한다. 잘못된 조작의 실제 벽 접촉은 기존 판정을 적용하되, 올바른 조작으로 대표 코너를 통과할 때 반복 접촉이 생기면 물리를 먼저 고친다.

## 충전과 종료 보상

현재 기본 기체는 자연 충전이 초당 16%, 니어미스 보상이 8%다. 드리프트는 자연 충전을 유지하고 **정상 종료 시 한 번만 추가 충전**한다. 진행 중 단계 표시는 예약 보상이며 배터리에 미리 넣지 않는다.

유효 시간은 활성 상태에서 속도/곡률 유지 조건을 충족하고 실제 `abs(heading) >= 0.07rad(약 4°)`인 시간이다. 진입 대기나 일시정지·정지 안내 시간은 포함하지 않는다.

| 충전 단계 | 누적 유효 시간 | 종료 추가 충전 |
| --- | --- | --- |
| 0 | 0.6초 미만 | 0% |
| 1 | 0.6초 이상 | 5% (`0.05`) |
| 2 | 1.2초 이상 | 10% (`0.10`) |
| 3 | 2.0초 이상 | 15% (`0.15`, 최대) |

브레이크 해제·조향 중립/반전·코너 종료·속도 하한 도달·분기 보정 진입·점프 발사·각성 발동은 정상 종료로 현재 단계를 정산한다. 부스트는 기존대로 브레이크 중 작동하지 않는다. 브레이크를 놓고 부스트를 누른 프레임에는 드리프트 보상을 먼저 정산하고 부스트 시작을 판정한다.

벽/장애물/NPC 충돌·코스 이탈·복구·재시작·레이스 종료는 예약 보상을 취소한다. 같은 고정 시간 스텝에 종료와 충돌이 겹치면 충돌 취소가 우선한다. 일시정지는 누적 시간을 동결하고 입력을 초기화한다. 재개 첫 스텝에는 해제된 입력에 따라 정상 종료를 정산한다. 정지한 시간은 단계 충전이나 자연 충전에 포함하지 않는다.

총 저장 한도 **150%**, 한 번의 부스트 사용 한도 **100%**를 유지한다. 추가 충전은 `min(1.5, charge + reward)`이며 보상 이벤트에는 실제 늘어난 양과 예약 보상 둘 다 넣는다. 배터리가 가득 차도 달성 단계는 보여 줄 수 있다. 드리프트가 부스트 소비 한도·해제 잠금·피격 충전 지연을 초기화하지 않는다.

## 니어미스·클린 콤보와의 관계

- 드리프트 중 실제 니어미스가 발생하면 기존 8% 충전과 횟수 집계를 그대로 적용한다. 드리프트 보상도 정상 종료하면 더한다. 곱셈 배율은 없다.
- `cleanStreak`은 장애물을 충돌 없이 통과한 연속 횟수다. 드리프트 자체가 `nearMisses`, `cleanStreak`, `obstaclesPassed`, `boostUses`를 증가시키지 않는다.
- 실제 충돌은 기존 클린 연속을 끊고 드리프트 예약 보상도 취소한다. 클린 반랩·통과 포인트·기록 보너스 판정도 기존 규칙을 따른다.
- 첫 구현에서 추가 지갑 포인트나 드리프트 전용 결과 카드·영구 통계를 만들지 않는다. 선택 기술의 보상은 더 자주 사용할 수 있는 부스트다.
- NPC에는 첫 구현의 드리프트를 활성화하지 않는다. 기존 AI의 감속+조향이 자동으로 새 보상을 얻거나 난이도가 올라가지 않게 모델 생성 옵션으로 플레이어만 켠다.

## 화면 상태 계약

Codex는 DOM/Three.js 없는 `src/game/driving/drift.ts`에 타입·설정·상태 전이/보상 계산을 두고 `createDrivingModel.ts`에서 기존 물리에 연결한다. `DrivingState`에 `drift: DriftSnapshot`을 추가한다. `RaceSnapshot extends DrivingState`이므로 화면은 `snapshot.drift`로 읽는다. 별도 UI 이벤트 버스를 추가하지 않는다.

```ts
// export: src/game/driving/drift.ts
export type DriftStage = 0 | 1 | 2 | 3;
export type DriftDirection = -1 | 0 | 1; // 트랙 프레임 기준 왼쪽/없음/오른쪽
export interface DriftReward {
  id: number;                   // 레이스 내 증가 ID, 한 종료를 한 번만 표시
  stage: DriftStage;
  earnedCharge: number;         // 단계 보상: 0 / .05 / .10 / .15
  addedCharge: number;          // 150% 상한 적용 후 실제 충전량
  cancelled: boolean;
}
export interface DriftSnapshot {
  active: boolean;
  direction: DriftDirection;
  angle: number;                // signed radians, 현재 heading; 비활성 시 0
  seconds: number;              // 누적 유효 시간, 활성 중에만 값 유지
  stage: DriftStage;
  stageProgress: number;        // 다음 단계까지 0..1, 3단계면 1
  pendingCharge: number;        // 아직 배터리에 넣지 않은 현재 단계 보상
  lastReward: DriftReward | null;
}
// DrivingState 추가 필드
// drift: DriftSnapshot;
```

`stageProgress`는 각 시간 구간 `[0, .6]`, `[.6, 1.2]`, `[1.2, 2]`에서 선형으로 증가한다. 단계가 올라가면 다음 구간의 0으로 돌아가므로 전체 진행률로 해석하지 않는다. 활성화 전에는 `active=false`, `direction=0`, `angle/seconds/stage/stageProgress/pendingCharge=0`이다. 종료 후에도 `lastReward`는 다음 종료까지 남는다. 재시작은 ID와 이벤트를 초기화한다. 화면은 직전 ID와 비교해 종료 이펙트를 한 번 재생한다. 단계 0 종료도 이벤트를 내되 충전 이펙트는 생략한다. 취소는 `earnedCharge`에 취소 직전 예약값을 남기고 `addedCharge=0`, `cancelled=true`다.

화면은 `active/angle/direction`으로 추진기 궤적, `stage/stageProgress/pendingCharge`로 스파크와 충전 단계, `lastReward`로 종료 보상을 표시한다. `charge`가 실제 배터리이며 예약값을 합쳐 표시하지 않는다. 기체 자세는 기존 heading 표시를 따르고 이펙트가 물리에 값을 되쓰지 않는다. 구체적 색·위치·크기는 Claude 담당이다.

## 구현 검증과 기록

고정 120Hz 시간으로 진입·단계·정산을 계산한다. 렌더 프레임률에 따라 충전량이 달라지지 않아야 한다. 최소 회귀 검증:

1. 브레이크 단독/직선/잘못된 조향/저속은 진입·추가 보상이 없다. 키보드·터치 아래 대각선·게임패드 입력이 같은 상태 전이로 이어진다.
2. .6/1.2/2초 경계와 각 종료 조건, 같은 스텝 충돌 취소, 일시정지, 재시작, 150% 상한, 이후 단일 부스트 100% 소비를 검사한다.
3. 니어미스·클린 연속·피격·부스트 집계가 중복되거나 소실되지 않는지 검사한다. 드리프트를 사용하지 않는 기존 입력과 NPC 동작은 기존 물리를 유지한다.
4. 5기체 × 3난이도에서 네온/마린 대표 좌우 코너·롤/루프·분기·점프를 검사한다. 기본/드리프트를 비교해 속도·횡각·횡이동·충돌·추가 충전을 기록하고, 기존 `audit:forks`의 3,300회 무접촉과 곡률 기준도 통과한다.
5. 실제 브라우저에서 데스크톱 키 홀드와 모바일 대각선 입력의 진입·종료·배터리 표시를 확인한다. 프레임률 30/60/120Hz 입력의 총 충전 차이는 고정 스텝 1개 오차 이내다.

캠페인 48트랙의 revision을 각각 1 올렸다(마린 2 → 3). 새 물리의 최고 시간/고스트 비교를 이전 버전과 분리하며 해금·통과·지갑은 보존한다. 앱 버전은 올리지 않았다. 로드맵 완료 체크와 앱 버전은 사용자 요청에 따른 최종 머지에서 처리한다.


### 생성 옵션과 연결 경계

`createDrivingModel(track, performance?, options?: { drift?: boolean })`의 기본값은 꺼짐이다. `createTimeAttack`은 `RaceRules.drift?: boolean`으로 제어하며 일반 플레이어는 기본으로 켠다. NPC는 `createRaceSession`에서 명시적으로 끈다. `createRace`의 rules에 `drift: !guidance.tutorial` 한 필드만 추가했으므로 일반 연습·기능 테스트에서도 켜지고 튜토리얼에서는 꺼진다. Claude는 이 필드를 유지하고 `snapshot.drift`만 읽어 이펙트를 연결하면 된다.

순수 모듈은 위 타입 외에 `DRIFT_TUNING`, `DriftConditions`, `driftStage(seconds: number): DriftStage`, `createDriftController()`를 export한다. 컨트롤러는 `snapshot/prepare/blend/advance/finish/revoke/reset`으로 모델 내부에서만 사용한다. `model.cancelDrift(): void`는 충돌·복구·레이스 종료 시 사용한다.

긴 충전은 도로 폭에 맞춰 조향을 조절해야 한다. 2초 동안 최대 조향을 계속 누르는 모든 조건의 무접촉을 보장하지 않는다. 3단계 시간·보상은 넓은 코너 회귀 테스트에서 확인했다. 물리 스텝은 기존 120Hz이며 30/60/120Hz 호출에서 같은 종료 보상을 확인했다.

기존 분기 입력 감사도 플레이어 드리프트 옵션을 켠 모델로 실행했다. 55경로 × 5기체 × 3난이도 × 일반/부스트 × 확정 후 홀드 .2초/1.5초 = 3,300회 모두 도달·선택 성공, 벽 접촉·코스 이탈 0. 분기 형상과 선택 경계는 변경하지 않았다(입구~분리 후 100m 최대 횡곡률 기존 ≤ .012m⁻¹ 유지).
