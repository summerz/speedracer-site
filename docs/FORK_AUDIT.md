# 분기 주행 감사와 개선

기준선은 배포 main `86e3f74`(0.19.19)이다. 캠페인 48트랙 전체에서 분기가 있는 **19트랙·39경로**를 검사하고 공통 진입 형상과 선택 조향을 수정했다.

## 판정 기준과 결과

- 형상: 입구 `start`부터 확정 뒤 **물리 거리 100m**까지 1m 간격으로 검사한다. 횡곡률은 **≤ 0.012m⁻¹**이어야 한다. 헤딩 변화는 3D 접선 각도(°/m)이며, 횡가속 G는 80m/s(288km/h)에서의 형상 비교 지표다.
- 입력: 입구 180m 전부터 목표 방향으로 최대 조향하고, 확정 뒤 0.2초 또는 **1.5초** 더 홀드한다. 이후에는 offset·heading만으로 중앙 복귀한다. 곡률 예측이나 경로 추적 AI를 사용하지 않는다. 고도 분기는 목표 고도에서 시작한다.
- 실패: 목표와 다른 경로 확정, 확정 뒤 100m 미도달, 벽 접촉 또는 코스 이탈. 1.5초 홀드는 해당 시간과 복귀 0.4초가 끝날 때까지도 검사한다.
- 검사 범위: 의도된 장애물·점프·아이템을 제거하고 분기 진입 조작을 분리한다. 분기 몸체 전체를 최대 부스트로 무조작 통과한다는 보장은 아니다. 몸체의 일반 굽이·위험 요소에는 계속 조향·감속이 필요하다.
- 간격: 공통 입구·Y 입구·합류를 제외한 독립 몸체 사이 최근접 3D 중심선 거리(공유 진행 거리 4m 샘플)다. 기울어진 노면의 실제 겹침은 경계 생성 회귀 검사로 별도 확인한다.

| 검사 | 수정 전 | 수정 후 |
|---|---:|---:|
| 기본/고속 2기체 × 3난이도 × 일반/부스트, 0.2초 홀드 | 291/468 실패, 30경로 | 0/468 실패 |
| 전체 5기체 × 3난이도 × 일반/부스트, 0.2초 홀드 | — | 0/1,170 실패 |
| 전체 5기체 × 3난이도 × 일반/부스트, 1.5초 홀드 | — | 0/1,170 실패 |
| 입구 최대 횡곡률 | 0.05254m⁻¹ | 0.01186m⁻¹ |
| 80m/s 형상 횡가속 최대 | 34.27G | 7.74G |

5기체 확장 **2,340회 모두 오선택·벽 접촉·코스 이탈 0**, 39경로 모두 곡률 기준을 만족한다. 2기체 수정 후 수치는 5기체 검사 중 동일 기체의 부분집합이다.

## 적용 내용과 시각 연결 계약

1. 첫 번째로 나타나는 짧은 구간 대신 충분히 긴 연속 구간을 우선 선택한다. 짧은 분기에서는 Y 분리·합류 비중을 늘리고 몸체 횡이동을 줄인다. ARENA RING의 오른쪽 돌출도 줄였다.
2. 좌측 몸체의 짧은 반복 S자를 완화하고, Y 횡분리와 고도 상승 시작을 나눴다. 코일의 타원·교차·노면 회전과 일반 분기의 한 바퀴 롤은 유지하되 짧은 롤 구간의 회전 속도를 완화했다.
3. 모든 분기의 입구에서 지속 조향을 차선 선택으로 받는다. 경로 확정 후 Y 진입 및 1.7초 전환 여유 동안 같은 방향 홀드·중립 입력은 중심으로 완만하게 복귀한다. 반대 방향 입력은 계속 작동하며 실제 벽·장애물 충돌 판정도 유지한다.
4. Y의 겹치는 안쪽 노면 경계를 로컬 좌우 축에서 잘라 상승 구간의 노면 접힘을 방지한다.
5. 코일 전기선은 Y 끝에서 공유 진행 거리 **120m 이상** 뒤에 시작하고 합류 전에는 끝낸다. 차선 선택 입력을 놓고 안전한 쪽으로 이동할 여유다. 기존 전기선 AI 32랩 무접촉·링 획득 검사도 유지한다.
6. 랩 경계 너머의 첫 분기를 미리 알리고, 출발선 뒤 음수 거리 NPC도 첫 랩의 유효 경로를 선택한다.

**선택 경계는 변경하지 않았다.** 기존 2갈래는 `offset > 0.4m`이면 `routes[1]`, 그 외에는 `routes[0]`이다. ARENA RING은 좌우 `±0.3 × halfWidth`이며 중립은 가운데다. 공통 선택 구간 `start ~ start + junctionLength`도 2갈래 35m·3갈래 60m 그대로다. 일부 분기의 `start/end/mouthEnd/mergeStart`는 이동하므로 표지·차선·셰브론은 런타임 데이터를 읽는다. ARENA RING의 짧아진 몸체에 맞춰 고도 게이트·안전 통로·패드 위치를 조정했다.

기록에 영향을 주는 형상 변경이므로 **분기 19트랙의 revision을 각각 1 증가**했다. 비분기 트랙 revision과 앱 버전은 변경하지 않았다. TERRACE FLOW의 새 고도 선택 분기는 이번 변경에 포함하지 않았다.

## 재현과 검증

```sh
npm run audit:forks
npm run audit:forks -- --all-craft --json
npm run audit:forks -- --all-craft --hold --json
npm test
npm run build
npm run docs:world:check
```

감사 CLI는 진입 실패 또는 곡률 기준 초과 시 종료 코드 1을 반환한다. `tests/forkAudit.test.mjs`는 2,340회 주행, 랩 경계, 음수 그리드 거리, 전기선 여유, 반대 입력과 실제 벽 접촉을 회귀 검사로 고정한다.

최종 검증: 전체 테스트 **604/604**, 타입 검사와 운영 빌드, `docs:world:check` 통과. 실제 `createRace`를 띄운 브라우저에서도 ARENA RING의 쉬움·보통·어려움 각각 A/D 키를 안내 시작부터 확정 후 1.5초까지 유지했다. 의도한 좌·우 경로로 모두 진입했고 6회 모두 접촉·코스 이탈 0, 브라우저 콘솔 오류 0이었다. 이 브라우저 검사는 실제 장애물을 유지했으며, 39경로 전체 스트레스 검사는 앞서 설명한 대로 진입 형상과 조향만 분리해 검사한다.
