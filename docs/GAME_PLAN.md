# 드론 레이싱 게임 개발 계획

작성일: 2026-10-04

상태: P2 사용자 조정·모바일 터치와 부스트 진동 구현·기술 검증 완료, P3 대기

Three.js로 브라우저에서 실행되는 미래형 드론 레이싱 게임을 만든다. 첫 버전은 트랙 중심의 아케이드 조종과 싱글 타임어택이다. 코너를 통과하고 부스트 타이밍을 조절해 기록을 줄이는 재미를 먼저 검증한다. 이후 AI 경쟁과 경기 보상, 장비 구매를 추가한다.

진행 상황과 검증 결과는 [개발 체크리스트](DEVELOPMENT_CHECKLIST.md)에 기록한다.

## 확정된 방향

| 항목 | 결정 |
| --- | --- |
| 실행 환경 | 브라우저 |
| 3D 구현 | Three.js |
| 플레이어 기체 | 사람이 탑승하는 미래형 레이싱 드론 |
| 조종 방식 | 트랙 중심의 아케이드 조종, 좌우 조향과 제한된 고도 조절 |
| 첫 경기 모드 | 싱글 타임어택 |
| 시점 | 콕핏과 전체 레이스를 내려다보는 뷰 전환 |
| 시각 방향 | 어두운 입체 표면, 주요 구조의 네온선, Bloom |
| 성장 방향 | 경기 포인트로 장비를 구매하고 성능 개선 |
| 추진 효과 | 가속·부스트에 반응하는 불꽃과 잔광; 배기 뒤 아지랑이는 선택 효과로 성능 비교 후 적용 |
| 조종감의 중심 | 속도감과 타격감, 빠른 입력 반응과 시원하게 달리는 감각 |
| 입체 트랙 | 첫 트랙에서 큰 오르내림, 수직 루프, 스프링처럼 감기는 나선형 구간 시험 |

조정의 우선순위는 빠른 입력 반응, 가속·부스트의 뚜렷한 변화, 접촉 순간의 선명한 피드백이다. 경사를 크게 타고 넘어도 속도를 유지하는 아케이드 비행을 기준으로 한다. 방전 장벽에는 큰 감속과 순간 발광을 연결했고, 공격·피격 시스템은 후속 범위다. 타격 관련 기능을 추가할 때도 충격 순간, 상대의 반응, 화면·소리의 피드백을 함께 설계한다.

## 첫 버전의 범위

기체 한 대와 순환 트랙 하나로 출발부터 완주, 결과 확인, 재도전까지 연결한다. 기록과 조종감을 검증한 뒤 AI 경쟁과 성장 시스템으로 확장한다.

- 가속, 감속, 좌우 조향, 제한된 고도 조절, 부스트.
- 콕핏과 전체 트랙 뷰 전환. 시점을 바꿔도 경기 상태와 조작은 이어진다.
- 카운트다운, 체크포인트, 랩 판정, 경기 시간, 결과 화면.
- 브라우저에 최고 기록 저장.
- 충돌 감속, 트랙 이탈 복귀, 일시정지, 재시작.
- 네온과 Bloom, 가속에 반응하는 추진 효과와 기본 사운드.

AI 경쟁, 포인트와 차고, 추가 트랙은 후속 단계에서 구현한다. 모바일은 자동 가속과 터치 조작을 지원한다. 온라인 멀티플레이, 계정과 서버 저장은 현재 계획에 포함하지 않는다.

## 초기 플레이 설계

이 절의 랩 수, 키 배치, 세부 규칙은 구현 출발점으로 제안한 값이다. 실제 주행 검증 후 조정하고 변경 이유를 기록한다.

### 조종과 트랙

- 기본 비행 높이는 트랙의 높낮이를 따라가고, 플레이어는 허용 범위에서 상대 고도를 조절한다.
- 플레이어가 코너에 맞춰 직접 조향한다. 속도와 조향에 따라 바깥으로 밀리는 정도를 조정한다.
- 첫 트랙에 긴 직선, 완만한 코너, 급한 코너, 상승과 하강 구간을 배치한다.
- 충돌은 감속으로 처리한다. 크게 이탈하면 마지막으로 정상 통과한 체크포인트로 복귀하고 속도를 낮춘다.
- 부스트는 한정된 게이지를 사용한다. 사용량과 회복 속도는 주행하며 조정한다.

| 키 | 동작 |
| --- | --- |
| 자동 / S | 자동 가속 / 누르는 동안 감속 |
| A / D | 좌우 조향 |
| Q / E | 한 번 눌러 인접 단계로 하강 / 상승 |
| Space | 부스트 |
| C | 추적 → 콕핏 → 전체 트랙 뷰 전환 |
| F | 마지막 정상 체크포인트로 복귀 |
| R | 경기 재시작 |
| Esc | 일시정지 / 계속하기 |

### 난이도와 트랙 복잡도

난이도는 트랙 복잡도, 장애물 배치, 고도 단계 수를 조합한 프리셋으로 구성한다. 주행 시작 화면의 시작 버튼 위에서 초급·중급·고급을 선택하고, 트랙 특징과 고도 단계 수를 함께 안내한다. 이후 트랙 선택 화면으로 확장한다. 아래 프리셋을 구현하고 자동 테스트와 Chrome 주행으로 검증했다. 재미와 조작 부담은 사용자 주행 후 조정한다.

| 난이도 | 트랙 구성 | 장애물과 고도 |
| --- | --- | --- |
| 초급 | 폭 28m, 완만한 코너, 스프링 1회전·전진 간격 300m, 약 3,544m | 2단계 고도, 상단·하단 방전 장애물 6개 |
| 중급 | 폭 22m, 연속 코너, 스프링 2회전·전진 간격 260m, 약 4,112m | 3단계 고도, 중간 고도 통과 구간을 포함한 장애물 8개 |
| 고급 | 폭 18m, 연속 S 코너와 높낮이 변화, 스프링 3회전·전진 간격 220m, 약 4,672m | 4단계 고도, 서로 다른 안전 고도를 요구하는 장애물 12개 |

루프·스프링의 회전은 자동으로 따라가므로 회전 구간 자체의 시각적 혼란과 실제 조향·회피 요구를 따로 검토한다. 회전 직후의 코너, 다음 구간이 보이는 거리, 장애물과의 간격이 실제 난이도에 영향을 준다. 다음 경로와 안전 고도를 읽을 단서는 유지한다. 속도감과 시원한 조작감을 유지하도록 기본 최고 속도는 난이도별로 낮추지 않고 기체·장비 성능 설정에서 관리한다.

트랙 형태·폭·구간 배치 설정, 장애물 배치 설정, `AltitudeProfile`은 독립적으로 구성하고 난이도 프리셋이 이들을 조합한다. 따라서 새 트랙이나 이벤트에서 같은 고도 단계 수로도 서로 다른 난이도를 만들 수 있다. 난이도 선택 UI, 트랙 복잡도 차이, 중간 고도 통과 장애물을 함께 구현했다. 38개 자동 테스트와 중급 콕핏 한 바퀴 주행을 통과했다. 난이도별 실제 조작 부담과 시각적 혼란은 사용자 검토를 남겨 둔다.

### P1·P2 구현과 조정값

격납고의 **주행 테스트**로 진입하거나 `/#drive`를 직접 연다. 현재는 `C`로 추적·콕핏을 전환하고 `X`로 주행만·트랙 PIP·트랙 메인/주행 PIP를 순환하며 자유 주행한다. 랩 판정과 기록 저장은 P3에서 구현한다. 표시되는 경과 시간은 연습 시간이다.

초급·중급·고급 트랙은 각각 약 3,544m·4,112m·4,672m이며 폭은 28m·22m·18m다. 각 트랙의 복귀 체크포인트 24개를 주황색 반원 아치로 표시한다. 첫 직선 다음에 약 136m 높이의 수직 루프, 이어서 반경 44m의 스프링을 난이도별 1·2·3회전 배치했다. 한 바퀴당 전진 간격은 300m·260m·220m다. 이후 큰 오르내림과 코너를 거쳐 출발점으로 돌아온다. 수직 루프 입구와 출구는 옆으로 48m 떨어져 있고 스프링도 전진 간격을 두어 노면끼리 겹치지 않는다. 프리셋 없이 직접 생성하는 기존 트랙은 폭 22m·스프링 2회전 구성을 유지한다.

기본 최고 속도는 55m/s(198km/h), 부스트 1단계 최고 속도는 82m/s(약 295km/h), 2단계는 96m/s(약 346km/h)다. 가속은 30m/s², 감속은 44m/s², 부스트 가속은 1단계 48m/s²·2단계 64m/s², 관성 주행 감속은 5m/s²다. Q/E 한 번은 현재 목표 고도에서 인접 단계로 이동하고 키를 놓아도 선택한 높이까지 이동한다. UI에서 난이도별 2·3·4단계를 선택하며 인접 단계 전환은 약 0.2초다. 고도는 세계의 위아래가 아니라 노면의 위쪽을 기준으로 한다. 수직·뒤집힌 구간에서도 노면 위의 높이를 유지한다.

고도 단계는 트랙·난이도 설정 `AltitudeProfile`에 둔다. `levels`는 오름차순의 실제 높이 목록, `initialLevel`은 시작·복귀 단계, `transitionSeconds`는 인접 단계 전환 시간이다. 초급 2단계 `[1.8, 6.2]`, 중급 3단계 `[1.8, 4, 6.2]`, 고급 4단계 `[1.8, 3.2, 4.7, 6.2]`를 제공하고 같은 방식으로 N단계를 지정할 수 있다. 빠른 연속 탭은 목표 단계를 한 칸씩 바꾸며 최저·최고에서 멈춘다. HUD는 현재 목표 단계/전체 단계 수와 안전 고도까지 필요한 Q/E 횟수를 표시한다. 중급·고급에는 중간 고도만 안전한 장애물을 배치했다. 상·하단 방전 아크 사이로 통과하며 안전 높이 구간으로 판정하므로 단계 수에 의존하지 않는다.

고도 조종을 실제 통과 조건으로 사용한다. 초급은 상단·하단 방전 장벽 6개, 중급은 8개, 고급은 12개이며 중급부터 중간 고도 통과 장애물을 포함한다. 양쪽 접지 기둥 사이로 불규칙한 전기 아크가 흐르고 앞이 보인다. 프리셋의 하단 장벽은 고도 5.75m 이상, 상단 장벽은 2.25m 이하에서 통과하며 중간 통과 구간은 지정 고도 ±0.45m다. 화면 안내는 한 자리 소수로 표시한다. 높이가 맞지 않으면 그대로 통과하며 속도가 접촉 직전의 35%로 줄어든다. 같은 장벽 안에서 감속이 중복되지 않고 다음 바퀴에는 다시 판정한다. 충돌 판정은 개별 아크 사이의 틈이 아닌 장벽의 안전 높이 영역을 기준으로 한다. 접촉 순간에는 아크가 두껍고 밝아지고 화면 전체에 짧은 섬광을 표시한다. 고도계는 현재 높이, 다음 장벽의 안전 높이와 남은 거리를 보여준다. 기존 프리셋 없는 트랙의 안전 높이 5.2m·2.7m는 호환성을 위해 유지한다.

추적 카메라는 기체 뒤 8.5m, 위 3.5m를 기준으로 노면의 경사와 회전을 따라 기울어진다. 수직 루프 꼭대기와 스프링 반 바퀴에서는 지평선도 뒤집힌다. 오르막에서 앞을 올려다보고 내리막에서 아래 구간이 펼쳐진다. 위치는 기체 이동을 바로 따라가고 상대 카메라 방향만 부드럽게 보정한다. 가속·부스트의 시야각 변화에 맞춰 거리를 보정해 기체 크기를 유지한다. 가까운 바닥 표시는 속도에 반응한다. 빗금은 부스트 중에만 표시하고 2단계에서 더 굵고 진해진다. 2단계 진입 시 카메라가 최대 2.4m 뒤로 밀렸다가 약 0.45초 안에 따라붙고 시야각도 순간 확장한다. 유지 중에는 화면 외곽의 공간 왜곡·방사형 잔상을 적용하며 중앙 트랙과 HTML HUD는 선명하게 유지한다. 움직임 줄이기 설정에서는 시야각 확장·카메라 충격·공간 왜곡·흐름선을 끄고 충돌 섬광을 약하게 한다. 부스트 연출은 사용자 요청에 따라 현재 수준에서 정리했으며 추가 체감 개선은 후속 검토로 남긴다.

부스트는 완충 시 5초 동안 사용할 수 있다. 연속 사용 시간이 완충 지속 시간의 60%(기본 3초)에 도달하면 2단계로 전환한다. 키 해제·제동·복귀·재시작·일시정지·소진 시 연속 사용 시간이 초기화된다. 준비 게이지, 추진 색·충격파와 합성 부스트음을 연결했으며 음향 버튼으로 끌 수 있다. 종료 후 0.8초 지연 뒤 초당 16% 회복한다. 소진 후 키를 계속 누르고 있어도 재발동하지 않으며, 잔량이 15% 이상일 때 Space를 놓았다가 다시 눌러야 한다. 감속 입력이 가속과 부스트보다 우선한다.

트랙의 곡률과 조향으로 상대 진행 각도와 옆 방향 이동을 계산한다. 최대 조향 속도는 1.5rad/s에서 속도에 따라 감소하며 급한 코너에서는 감속이 필요하다. 코너 반경은 도로 폭에 비해 충분히 크게 유지한다. 일반 코너는 노면의 오른쪽 방향으로 굽는 곡률을 사용한다. 수직 루프와 스프링은 자동으로 진행 방향과 자세를 따라가므로 추가 회전 조작이 필요 없다. 낮은 고도에서 경계에 닿으면 속도가 62%로 줄고, 상대 고도 3.2m 위에서는 경계를 넘을 수 있으나 크게 이탈하면 마지막 정상 체크포인트로 복귀한다.

운동은 최대 1/120초 단위로 나누며 긴 프레임은 0.1초까지 처리한다. 브라우저 키 입력을 자동 조절한 검증에서 충돌과 복귀 없이 한 바퀴를 주행했다. 이 결과는 기술 검증이며, 조종감의 재미와 난이도는 사용자 주행 후 조정한다.

기체별 `DroneConfiguration`은 실제 주행 성능과 속도 연출 값을 따로 갖는다. 장비의 배율을 합성해 최고 속도·가속·조향·부스트 효율을 변경하고 연출 값을 별도로 조정할 수 있다. 이 설정은 실제 주행 모델과 렌더링에 연결되어 있다. 구매·장착 UI와 저장은 P6에서 구현한다.

### 첫 트랙의 입체 구간과 확장

사용자 요청으로 아래 입체 구간을 첫 트랙에 함께 배치했다. 실제 주행 감각을 확인한 뒤 회전 반경·횟수·연속 배치와 추가 트랙을 조정한다.

| 형태 | 주행 경험 | 구현 기준 |
| --- | --- | --- |
| 큰 오르내림 | 능선을 넘어 아래 구간으로 빠르게 진입 | 현재 첫 트랙의 높이 변화와 경사 카메라 |
| 꽈배기·스프링·나선형 | 트랙을 따라 빙글 돌며 배경과 지평선이 회전하는 큰 시각적 변화 | 트랙을 따르는 자동 자세·회전, 회전 반경과 구간 간격, 매끄러운 진입·이탈 |
| 수직 루프 | 크게 솟았다가 뒤집힌 자세를 거쳐 한 바퀴 통과 | 현재 첫 트랙의 약 136m 높이 루프, 자동 자세·카메라 회전 |

여기서 ‘꽈배기’는 스프링처럼 빙글 도는 주행 경험을 뜻한다. 기체는 노면에서 일정 높이를 유지하고, 트랙에 따른 상하 변화와 회전을 기체·카메라가 자동으로 따라간다. 별도의 롤 조작은 추가하지 않는다. 노면이 회전하는 직선 구간에서는 추가 조향 없이 통과하고, 실제 코너와 장애물 회피에는 A/D를 사용한다. 방향감이 잠시 흔들리는 시각적 변화와 빠르게 통과하는 시원한 감각을 의도한다. 자동 회전만으로 일반 코너 조향까지 대체하지 않도록 구간의 회전과 진행 방향의 굽힘을 구분한다.

입체 트랙에서는 샘플마다 위치·진행 방향·노면 오른쪽·노면 위쪽을 제공한다. 좌우 조작은 노면의 오른쪽, Q/E는 노면에서 떨어진 거리로 유지한다. 기체·추적 및 콕핏 카메라·아치·장애물·복귀 지점은 같은 좌표계를 사용한다. 현재 첫 트랙은 이 노면 좌표계를 사용한다. 위치와 회전은 거리 기준으로 보간하고 수직 방향에서도 오른쪽 벡터가 사라지지 않는다. 노면 회전은 연속적으로 보간하고 닫힌 트랙의 접합부에서도 자세가 튀지 않게 한다. 서로 겹쳐 보이는 구간의 간격과 고속 통과 판정도 검증한다. 회전 중에는 지평선과 주변 구조물이 크게 변하되 다음 구간과 회피할 장애물을 읽을 단서를 유지한다.

### P2 시점 구현

`C` 또는 시점 버튼은 추적 ↔ 콕핏을 전환한다. `X` 또는 트랙 버튼은 주행만 → 주행 메인·트랙 PIP → 전체 트랙 메인·주행 PIP → 주행만으로 순환한다. 콕핏 선택은 화면 배치와 독립적으로 유지한다. 주행 중 전환해도 위치·속도·경과 시간·눌린 조작 상태가 이어지고, 일시정지 중에도 시점을 바꿀 수 있다. 재시작은 선택한 시점과 난이도를 유지한다. 난이도 버튼은 현재 연습을 초기화하고 시작 화면에서 새 트랙을 선택하게 한다.

콕핏은 기체의 `cockpitCameraMount`에 연결한다. 유리를 숨기고 계기판 밝기를 낮춰 중앙 전방 시야를 확보했다. 노면의 뒤집힌 자세는 그대로 따르며 기체의 추가 조향 기울기는 별도 강도 0.35, 부스트 흔들림은 0.008로 조절한다. 움직임 줄이기 설정에서는 추가 기울기·흔들림을 끈다.

전체 뷰는 화면 비율에 맞춰 트랙 전체를 담고 안개를 끈다. 2.2px 폭 경로선과 흰색·주황색 플레이어 표식을 더했으며 전체 뷰에서는 빗금·외곽 왜곡을 숨긴다. Bloom을 꺼도 콕핏의 전방과 전체 뷰의 경로·표식을 읽을 수 있음을 빌드 미리보기에서 확인했다. Chrome에서 루프·스프링의 뒤집힌 콕핏 자세와 중급 한 바퀴 무충돌·무복귀 주행을 확인했다. 사용자 회전 체감, Safari와 GPU 프레임 시간 측정은 남아 있다.

### 경기와 기록

- 카운트다운 후 3랩을 주행한다.
- 모든 체크포인트를 순서대로 정상 통과한 경우에만 랩을 인정한다.
- 역주행, 지름길, 출발선 반복 통과, 이탈 복귀로 랩 수가 잘못 증가하지 않도록 한다.
- 결과에 총 주행 시간, 각 랩 시간, 최고 기록 갱신 여부를 표시한다.
- 일시정지 중 경기 시간은 멈춘다. 재시작하면 시간, 랩, 체크포인트, 부스트, 입력 상태를 초기화한다.
- 탭이 비활성화되거나 포커스를 잃으면 일시정지하고 입력을 해제한다. 복귀 후 사용자가 경기를 재개한다.
- 최고 기록은 트랙 식별자와 기록 규칙 버전을 함께 저장한다. 트랙이나 규칙이 바뀌면 이전 기록과 구분한다.
- 저장이 실패해도 완주와 결과 확인은 가능하게 하고, 기록을 저장하지 못했음을 표시한다.

### 카메라와 연출

- 콕핏에서는 중앙 시야를 확보하고 기체 기울기와 카메라 흔들림을 따로 조정한다.
- 전체 뷰에서는 트랙과 플레이어 위치를 한눈에 보여준다. AI 도입 후 참가 기체와 순위를 표시한다.
- 가까이 스치는 바닥 표시, 기둥, 경계선으로 이동 속도를 표현한다.
- 부스트 시 시야각, 추진 효과, 소리를 함께 변화시킨다.
- Bloom을 꺼도 기체와 트랙 경계가 읽히도록 한다.
- 추진 불꽃은 기존 기체의 좌우 추진 위치에 부착하고 뒤쪽으로 분사한다.

참고 코드의 `Thruster glow`는 추진부 재질의 색상 밝기를 조절하며 원본에는 분사 불꽃과 움직이는 잔광이 없다. P0 격납고에서 전달된 기체와 Bloom을 연결하고 Chrome에서 개발 서버와 빌드 미리보기를 검증했다. 사용자가 선 품질 문제를 지적하여 Bloom 렌더 타깃에 4× MSAA를 적용하고 받침 테두리 폭을 넓혔으며, 개선되었다는 피드백을 받았다. P2에서 전체 뷰의 경로를 픽셀 폭 선으로 보강하고 Bloom 없이 확인했다. 빠른 이동 중 먼 선의 깜빡임과 다른 GPU 검증은 남아 있다.

격납고에는 P4 추진 효과의 시각 테스트를 선행 구현했다. `1/2/3` 키와 버튼으로 대기·가속·부스트를 전환하며 밝기와 분사 길이, 잔광을 비교한다. 기본 불꽃은 따뜻한 흰색·주황·붉은색으로 기체의 청록색과 구분한다. 색 조합은 추진 상태와 분리된 `ThrusterStyle`로 지정하며 기체별 기본 스타일과 아이템 장착에 따른 실행 중 교체를 지원한다. 성능 업그레이드와 효과 변화의 구체적인 연결은 P4/P6에서 결정한다.

원본 자료는 `incoming-resources/`에 유지한다. 게임에서 사용하는 기체 모듈은 구현 단계에 프로젝트 소스로 옮겨 관리한다. 기체의 생성 코드를 활용해 색상과 추진 효과를 조절한다.

## 구현 구성

기술 구성은 TypeScript, Three.js, Vite를 사용한다. P0에서는 전달된 TypeScript 기체 생성 모듈과 Three.js의 UnrealBloomPass를 연결했다. 게임 실행은 원본 미리보기와 별도 진입점 및 업데이트 흐름으로 구성한다. 실행 방법과 파일 역할은 [로컬 개발과 실행](LOCAL_DEVELOPMENT.md)에 기록한다.

| 책임 | 내용 |
| --- | --- |
| 게임 진행 | 카운트다운, 주행, 일시정지, 결과와 재시작 |
| 입력과 기체 운동 | 조향, 가감속, 상대 고도, 부스트, 충돌과 복귀 |
| 트랙과 판정 | 트랙 형상, 체크포인트, 랩과 주행 방향 판정 |
| 카메라 | 콕핏과 전체 뷰 |
| 화면과 효과 | 렌더링, Bloom, 추진 효과, 계기 표시, 사운드 |
| 기록 저장 | 최고 기록과 후속 단계의 구매 및 장착 상태 |

이동과 판정은 렌더링 프레임 수에 좌우되지 않도록 한다. 시점이나 그래픽 품질을 바꿔도 경기 규칙은 유지한다. 고속으로 이동할 때도 벽과 체크포인트를 건너뛰지 않도록 이전 위치와 현재 위치 사이의 이동을 판정한다.

## 개발 단계

| 단계 | 결과물 | 완료 기준 |
| --- | --- | --- |
| P0 프로젝트 기반 | 개발 서버, 게임 진입점, 기체 표시 | 프로젝트에서 기체를 표시하고 오류 없이 실행 |
| P1 주행 프로토타입 | 단순 순환 트랙, 조종, 부스트, 충돌과 복귀 | 한 바퀴를 조종하며 코너와 고도 변화를 검증 |
| P2 속도감과 시점 | 콕핏, 전체 뷰, 네온, Bloom, 주변 구조물 | 속도와 부스트가 체감되고 시점 전환 중 주행이 이어짐 |
| P3 타임어택 | 경기 흐름, 체크포인트, 기록, 결과, 저장 | 3랩 완주와 재도전이 가능하고 유효 기록만 저장 |
| P4 추진 효과와 마무리 | 불꽃, 사운드, 품질 조절, 실행 검증 | 가속과 부스트의 효과가 일관되고 첫 버전 검증 항목 통과 |
| P5 경쟁 레이스 | AI 드론 3대, 순위, 추월과 충돌 | 참가자의 진행도와 최종 순위를 정확히 계산 |
| P6 성장 시스템 | 포인트, 차고, 구매와 장착, 진행 저장 | 구매한 장비의 효과가 다음 경기에 반영 |

P0부터 P4까지가 첫 타임어택 버전이다. P1 완료 후 조종감을 검토하고, P3 완료 후 재도전의 재미를 검토한다. 세부 조정값은 검증 결과를 바탕으로 정한다.

## 배기 아지랑이 실험 — P4

사용자 요청에 따라 추진부 불꽃 뒤에서 배경이 흔들리는 열 왜곡을 후속 효과로 검토한다. 작은 배기 영역의 노이즈로 배경 샘플 좌표를 조금 움직이고, 가속과 부스트에 따라 길이와 강도를 조절하는 방식부터 시험한다. 청록색 기체와 따뜻한 불꽃 색 조합은 유지한다.

- 왜곡 영역을 배기 뒤에 제한하고 저해상도 왜곡 버퍼부터 시험한다. 왜곡 처리 뒤 Bloom을 적용하는 구성을 비교한다.
- 품질 설정에 아지랑이 켜기·끄기를 제공하고, 움직임 줄이기 설정에서는 비활성화한다.
- 같은 트랙·카메라·해상도·주행 조건에서 끈 상태와 켠 상태의 프레임 시간 중앙값과 느린 프레임을 비교한다.
- 콕핏과 전체 뷰에서 시야를 방해하는지 확인한다. 성능 비용이나 시인성 문제가 크면 기본값을 끄거나 첫 버전에서 제외한다.

추가 버퍼와 화면 처리 비용은 아직 측정하지 않았다. P1 조종감 확인 뒤 진행하며 현재 구현에는 아지랑이가 포함되지 않는다.

## 성능과 검증 목표

- 초기 지원 목표는 PC의 Chrome과 키보드다. Safari에서도 첫 버전 실행과 주요 조작을 확인한다.
- 1920×1080 렌더링 해상도에서 60fps를 목표로 한다. 테스트 기기의 사양과 실제 렌더링 해상도를 기록하며, 현재 성능을 보장하는 수치는 아니다.
- 반복 주행 중 프레임 시간과 눈에 띄는 끊김을 확인한다. 고해상도 화면에서는 렌더링 해상도를 조절할 수 있게 한다.
- 브라우저 수동 검증은 조종, 시점, 화면, 사운드, 저장과 재시작을 중심으로 진행한다.
- 자동 검증은 체크포인트와 랩 판정, 부스트 제한, 프레임 변화에 따른 운동 차이 등 게임 규칙에 집중한다.

## 후속 성장 설계

경쟁 레이스를 완주하면 포인트를 얻고 차고에서 장비를 구매하거나 장착한다. 첫 장비는 추진기, 자세 제어 장치, 부스트 배터리로 한정한다.

| 장비 | 개선하는 성능 |
| --- | --- |
| 추진기 | 직선 최고 속도 |
| 자세 제어 장치 | 조향 반응과 코너 안정성 |
| 부스트 배터리 | 부스트 지속 시간 또는 회복 속도 |

보상량, 가격, 강화 수치와 경쟁 난이도는 P5와 P6에서 조정한다. 현재 구매 경제와 성능 수치는 확정하지 않았다.

## P3 전 사용자 조정 — 2026-10-04

- 일반 85m/s, 부스트 125m/s, 2단계 155m/s; 가속·감속과 조향 상향. 고속에서 코너링 여유가 감소하고 급한 코너에는 감속이 필요하다. 관련 수치는 기체·장비 성능 설정으로 관리한다.
- 고도는 Q/E에서 ↓/↑ 한 번으로 인접 단계를 선택하도록 변경한다. 왼손 A/D 조향·S 감속, 오른손 화살표 조작이며 기본은 자동 가속이다.
- C는 추적·콕핏만 전환하고 X는 트랙 PIP 표시·화면 교환·숨김을 순환한다. 부스트 중 기체 자체 진동은 장비별 연출 설정에서 조절한다.
- `summerz/speedracer-site`와 `speedracer.summerz.net`을 GitHub Pages로 연결한다. main 푸시 또는 수동 워크플로 실행으로 테스트·빌드 후 배포한다.
- 키 바인딩 변경·저장·기본값 복원은 후속 계획으로만 기록한다.
- 모바일은 자동 가속한다. 왼쪽에 좌우 조향·길게 누르는 감속, 오른쪽에 고도 단계 탭·길게 누르는 부스트를 제공한다. 동시 터치와 포인터 취소·일시정지 시 입력 해제를 지원한다.
- 부스트의 기기 진동은 1단계 진입 18ms, 2단계 진입 28ms·35ms 휴지·18ms 패턴으로 구분한다. 유지 중에는 0.7초마다 6ms, 2단계는 0.45초마다 10ms 맥동을 준다. 진동 API 지원·터치 기기에서만 사용하고 해제·일시정지·화면 이탈·진동 토글 끄기에서 취소한다. 움직임 줄이기에서는 끈다. 실제 기기별 강도와 지원 여부는 휴대폰 검토가 필요하다.

이 조정 이후 다음 구현 범위는 P3의 카운트다운·체크포인트 순서/방향·3랩 완주·결과·최고 기록 저장이다.

## P3 전 화면·설치 정리 (v0.2.0)

- 상단 주행 정보 축약, 우상단 일시정지·계속하기, 상세 정보·설정은 메뉴로 이동.
- 모바일 원형 조이스틱의 대각선 조향·감속, ㅏ 모양 고도·부스트 및 입력 해제 보완.
- 부스트 바로 왼쪽에 세로 N단계 고도선을 표시(높을수록 위). 실제 현재 고도는 굵은 청록색, 통과 고도는 주황색이며 장애물 접근 시 강조와 필요한 ↑/↓ 키·버튼 횟수를 안내. 충돌 문구는 주행 화면 상단에 짧게 표시. 고도·부스트·충돌 안내 모두 주행 PIP를 따라 이동.
- 웹앱 설치, 네온 드론 아이콘, 시작 로딩·재시도, 버전 표시, 명시적 업데이트와 최초 준비 후 오프라인 실행.

P3의 랩·결과·기록 저장은 아직 시작하지 않았다. 키 설정 변경도 기존 후속 계획으로 유지한다.

데스크톱도 자동 가속으로 모바일과 통일했다. S를 누르는 동안만 감속하며 해제하면 다시 가속한다. W는 필요하지 않다.

- 격납고 Bloom과 자동 회전은 기본 켜짐. 새 버전이 준비됐을 때만 업데이트 버튼을 표시하며 최신 버전 문구는 표시하지 않는다.
- 주행 준비는 난이도·시작, 일시정지는 계속하기·재시작·난이도 변경을 중심으로 정리한다. Bloom·음향·진동과 조작 안내는 별도 설정 팝업에 둔다. 현재 고도·다음 장애물·트랙 진행률 등 메뉴의 중복 정보는 제거한다.
- 정지 중 C/X 또는 시점 버튼으로 미리보기를 열면 큰 메뉴를 접고 하단의 시점·트랙·메뉴 복귀 버튼만 남긴다. 미리보기와 설정 팝업에서는 경기 시간이 정지하며, Esc로 설정·미리보기를 닫아도 자동 재개하지 않는다.
- 모바일 진행·멈춤 버튼은 44px로 줄이고 PIP 상단 우측에 겹쳐 배치한다. 트랙/주행 화면을 교환해도 같은 위치를 유지한다.
- 고도 단계가 실제 바뀔 때 8ms 진동을 준다. 경계에서의 무효 입력에는 진동이 없고 기존 진동 설정·움직임 줄이기를 따른다.
