# 로컬 개발과 실행

## 준비

Node.js 20.19 이상인 20.x 버전 또는 22.12 이상인 버전을 사용한다. P0 검증 환경은 macOS, Node.js 24.12.0, npm 11.6.2다.

프로젝트 루트에서 실행한다.

```sh
npm ci
npm run dev
```

브라우저에서 <http://127.0.0.1:5678>을 연다. 개발 서버는 로컬 주소에만 연결하며, 파일 변경 시 자동으로 반영한다. 포트가 사용 중이면 오류를 표시한다. 다른 포트로 실행하려면 `npm run dev -- --port 5275`를 사용한다.

## 검사와 배포용 빌드

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

`build`는 타입 검사 후 `dist/`에 배포용 정적 파일을 만든다. `preview`는 해당 파일(프로덕션 빌드)을 <http://127.0.0.1:5679>에서 확인하며, 5678의 dev 서버에는 영향이 없다. `dist/`가 없거나 소스를 바꾸었다면 먼저 다시 빌드한다.

개발 서버와 미리보기 서버는 터미널에서 `Ctrl+C`로 종료한다. GitHub Pages 배포는 [배포 안내](DEPLOYMENT.md)를 참고한다.

## 격납고

- 드래그: 기체를 중심으로 회전.
- 마우스 휠: 확대와 축소.
- 전면 / 후면 / 시점 초기화: 기체를 보는 방향 변경.
- 자동 회전: 지속 회전 켜기와 끄기.
- Bloom: 네온 주변 번짐 켜기와 끄기.
- `Q` 대기 / `W` 가속 / `E` 부스트: 불꽃 길이, 밝기와 추진부 발광 전환. 화면의 추진 테스트 버튼으로도 조작한다.

격납고에서 기체와 추진 효과를 미리 시험할 수 있다. 선택한 추진 상태는 다음 키나 버튼을 누를 때까지 유지된다. 새로고침하면 대기로 돌아간다. **타임어택** 버튼을 누르면 순환 트랙으로 이동한다.

불꽃은 따뜻한 흰색 중심부와 주황·붉은 꼬리로 구성한다. 노이즈가 흐르는 반투명 메시가 분사를 표현하고 부스트에서 짧게 사라지는 잔광 입자를 더한다. 상태를 전환하면 길이와 밝기, 기존 추진부 발광이 부드럽게 변한다. 움직임 줄이기 설정에서는 불꽃 패턴을 고정하고 입자를 끈다.

## 주행 테스트 — P2

<http://127.0.0.1:5678/#drive>에서 초급·중급·고급을 고른 뒤 **주행 시작**을 누른다. 선택 항목에 트랙 특징과 고도 단계 수가 표시된다. 추적 시점으로 시작하고 C로 추적·콕핏을 전환한다. X로 주행만 → 주행 메인·트랙 PIP → 트랙 메인·주행 PIP → 주행만을 순환한다.

| 키 / 버튼 | 동작 |
| --- | --- |
| 자동 / S | 자동 가속 / 누르는 동안 감속 |
| A / D | 좌우 조향 |
| ↓ / ↑ | 한 번 눌러 인접 고도 단계로 하강 / 상승 |
| C / 시점 | 추적 ↔ 콕핏; X 화면 배치와 독립 |
| X / 트랙 | 주행만 → 트랙 PIP → 트랙 메인·주행 PIP → 주행만; 주행 상태 유지 |
| 난이도 | 현재 연습을 초기화하고 시작 화면에서 난이도 선택 |
| Space | 연속 3초 후 2단계 부스트; 완충 5초, 소진 후 회복을 기다리고 키를 놓았다 다시 누름 |
| F | 마지막 정상 체크포인트로 복귀 |
| R / 다시 시작 | 위치·속도·시간·부스트와 입력 초기화 |
| Esc / 일시정지 | 일시정지 / 계속하기 |
| Bloom | 번짐 켜기 / 끄기 |
| 음향 | 합성 부스트음 켜기 / 끄기 |
| 진동 (지원 터치 기기) | 부스트 기기 진동 켜기 / 끄기 |
| 격납고 | 기체 미리보기로 돌아가기 |

코너에 맞춰 직접 조향한다. 급한 코너에서는 S로 감속하고 직선에서 부스트를 사용한다. 프리셋의 하단 방전 장벽은 노면 기준 고도 5.75m 이상, 상단 장벽은 2.25m 이하에서 통과한다. 중급·고급의 중간 통과 장애물은 안내된 높이 ±0.45m 구간이 안전하다. Vanguard에서 높이가 맞지 않으면 속도가 35%로 줄고 아크 발광과 화면 섬광이 생긴다. ↓/↑는 약 0.2초 안에 인접 단계로 전환한다. 트랙은 난이도별 약 3,544m·4,112m·4,672m이며 모두 136m 수직 루프와 각각 1·2·3회전 스프링을 포함한다. 기체와 추적·콕핏 카메라는 노면 회전을 자동으로 따르고 ↓/↑는 뒤집힌 곳에서도 노면 기준 높이를 조절한다. 주황색 반원 아치는 복귀 체크포인트다. 낮게 날다가 경계에 닿으면 감속하고 높게 날다가 크게 이탈하면 복귀한다. 창이 포커스를 잃으면 입력을 해제하고 일시정지하며 Esc 또는 계속하기로 재개한다.

현재는 3랩 타임어택이며 결과·최고 기록을 난이도와 기체 성능별로 저장한다. 터치 기기는 자동 가속하며 왼쪽 원형 조이스틱의 좌우로 조향하고 하단·하단 대각선으로 감속한다. 오른쪽 ↓/↑와 BOOST로 고도·부스트를 조작한다. 고도는 한 번 탭하고 조향·감속·부스트는 길게 누른다. 양손 동시 입력을 지원하며 일시정지·화면 이탈 시 입력을 해제한다. 설정에서 Bloom·효과음·음악·진동·렌더링 품질·배기 아지랑이를 조절한다. 진동은 지원 기기에서만 동작하며 iPhone Safari의 진동 미지원은 유지된다. 아지랑이는 기본 끔, 추적 시점 주행 중만 적용하고 움직임 줄이기에서는 비활성화한다.

## 소스 구성

| 파일 | 역할 |
| --- | --- |
| `src/main.ts` | 스타일, 폰트, 앱 시작과 개발 중 정리 |
| `src/app.ts` | 격납고 UI와 보기 조작, 화면 오류 표시 |
| `src/game/createHangar.ts` | 렌더러, 기본 장면, 카메라, Bloom, 크기 변경과 GPU 자원 정리 |
| `src/game/drone/createRacingDrone.ts` | 게임용 기체 생성 모듈 |
| `src/game/drone/createThrusterEffect.ts` | 추진 상태별 불꽃 셰이더, 잔광 입자와 스타일 설정 |
| `incoming-resources/` | 전달된 원본 자료와 참고 코드 |

기체 생성 모듈은 전달된 5종 TypeScript 소스를 적용했다. 공통 카메라·추진부 앵커와 콕핏 계기판 재질을 유지한다. 기체별 성능은 `droneCatalog.ts`에 두고 격납고 표시와 실제 주행에 같은 설정을 사용한다. 격납고의 조명, 네온 밝기와 Bloom 값은 장면 구성에서 조절한다. 폰트와 Three.js 모듈은 npm 의존성으로 포함하며 외부 CDN을 사용하지 않는다.

추진 효과의 `ThrusterStyle`은 `core`, `body`, `tail`, `afterglow` 색상을 갖는다. `createThrusterEffect(drone, scene, style)`로 기체별 초기 스타일을 지정하고, `setStyle(style)`로 장착 아이템에 따른 색 조합을 실행 중 교체할 수 있다. 격납고에서도 `setThrusterStyle(style)`로 연결한다. 색은 CSS 색상 문자열, 숫자 또는 `THREE.Color`를 받으며 셰이더와 GPU 자원을 재생성하지 않는다. `ThrustMode`는 별도로 길이·밝기·잔광량을 정한다. P1에서는 실제 가속·부스트 입력을 추진 상태에 연결했다. 장비 성능 수치와 스타일을 연결하는 규칙은 P6에서 확정한다.

Bloom을 적용하는 렌더 타깃에 4× MSAA를 설정하고 받침의 원형 테두리 폭을 넓혀 선 끊김을 완화했다. GPU가 지원하는 샘플 수는 기기에 따라 달라진다. 전체 트랙 뷰에는 2.2px 경로선을 더하고 Chrome에서 Bloom 없이 확인했다. 아주 먼 선과 빠른 이동 중 깜빡임, 다른 GPU의 표시 품질 검증은 남아 있다.

현재 빌드는 Three.js를 포함하는 JS가 약 685 kB이고 gzip 기준 약 180 kB다. Vite의 기본 500 kB 경고가 출력되지만 빌드는 성공한다. 기능이 늘어날 때 초기 로딩 비용과 모듈 분리를 검토한다.

## 검증 방법

개발 서버와 빌드 미리보기에서 기체, 앞뒤 보기, 회전, 확대와 축소, Bloom 전환을 확인한다. 추진 상태를 키와 버튼으로 전환하며 꼬리 길이, 발광, 선택 표시를 비교한다. 창 크기 변경 후 화면 비율과 UI를 확인하고 브라우저 콘솔에 오류가 없는지 점검한다.

Playwright로 생성한 검증 스크린샷은 `output/playwright/`에 저장한다. 이 폴더는 Git 추적에서 제외한다. 결과와 남은 문제는 [개발 체크리스트](DEVELOPMENT_CHECKLIST.md)에 기록한다. `npm test`는 주행 모델과 트랙 코드를 `output/test/`에 컴파일하고 Node.js 기본 테스트 러너로 55개 테스트를 실행한다. 30·60·120Hz 비교, 부스트 소진과 재입력, 제동 우선순위, 탭 고도 전환, 고속 충돌, 이탈 복귀, 무효 체크포인트, 긴 프레임과 초기화, 트랙 연결, 방전 장벽의 고속 감속과 통과, 다음 바퀴의 장벽 판정, 고도 조절을 포함한 한 바퀴 주행, 장비 합성과 실제 성능 반영, N단계 고도와 연속 탭·복귀, 수직 루프·스프링의 자동 추종과 좌표계 연속성, 떨어진 구간의 간격, 연속 부스트 2단계의 진입 시점·중단·소진·장비별 속도와 색 설정을 다룬다. 난이도별 폭·길이·장애물·고도, 세 프리셋의 좌표계 연속성과 구간 간격, 중간 고도 안전 통과, 화면 비율별 전체 뷰 범위도 검증한다.

## 기체와 장비 설정

`DroneConfiguration.performance`는 최고 속도·가속·제동·조향·부스트 소모와 회복을 정한다. `speedEffects`는 시야각, 2단계 진입 카메라 후퇴·확장량(`boostEntryPullback`, `boostEntryFovGain`), 외곽 왜곡 강도(`boostWarpStrength`, 0~1), 단계별 빗금 폭·불투명도를 정한다. 빗금은 부스트 중에만 표시한다. `referenceSpeed`를 유지한 채 실제 성능을 올리면 높은 속도에 맞춰 연출도 더 강해진다. 기체마다 별도의 연출 설정을 지정할 수 있다.

```ts
const equipped = resolveDroneConfiguration(DEFAULT_DRONE_CONFIGURATION, [
  {
    performanceMultiplier: { topSpeed: 1.1, acceleration: 1.15, maxYawRate: 1.1 },
    speedEffects: { boostFovGain: 10 },
  },
]);
const race = createRace(container, onUpdate, onError, equipped);
```

배율은 장비 순서대로 곱하고 연출 값은 뒤 장비의 지정 값으로 덮어쓴다. 원본 기체 설정을 변경하지 않으며 부스트 최고 속도는 일반 최고 속도 이상으로 보정한다. 재시작해도 장착 성능이 유지된다. 주행 부스트의 `boostStyle`은 충격파와 불꽃의 색 조합을 지정한다. 추진 효과 자체는 별도의 `ThrusterStyle`도 지원한다. 현재 UI는 기본 DR–01 설정을 사용하며 구매·장착·저장은 P6에서 연결한다.

## 난이도별 고도와 입체 구간

`src/game/track/altitudeProfile.ts`의 `ALTITUDE_PROFILES`는 초급 2단계·중급 3단계·고급 4단계 설정이다. `levels`에 실제 노면 위 높이를 오름차순으로 넣으면 같은 로직으로 N단계를 사용한다. 배열은 복제·동결되며 초기 단계와 전환 시간도 검증한다.

```ts
const race = createRace(container, onUpdate, onError, equipped, ALTITUDE_PROFILES.advanced);
// 또는 직접 설정: { levels: [1.8, 2.5, 3.7, 4.8, 6.2], initialLevel: 0, transitionSeconds: 0.2 }
```

현재 UI는 기본 초급이며 세 난이도를 선택할 수 있다. ↓/↑는 인접 목표 단계를 선택하고 반복 키 이벤트를 무시한다. 같은 프레임의 여러 탭도 순서를 보존한다. 고도계와 장벽 안내는 단계 목록에서 계산한다. 중간 고도 장애물은 아래·위 방전 아크 사이의 안전 구간으로 통과한다. `difficulty.ts`의 프리셋은 고도와 트랙 폭·코너·스프링 회전 수·전진 간격·장애물 목표 고도를 함께 지정한다.

```ts
const preset = DIFFICULTIES.advanced;
const race = createRace(container, onUpdate, onError, equipped, undefined, preset);
```

각 프리셋에는 약 136m 높이의 수직 루프와 반경 44m 스프링 1·2·3회전이 있다. `TrackFrame`의 `position`, `tangent`, `right`, `up`으로 기체·추적 및 콕핏 카메라·구조물을 배치한다. 고도와 좌우 조작은 각각 `up`과 `right` 기준이다. 회전 구간은 자동 추종하고 일반 코너는 A/D로 조향한다. `sections`는 구간 종류와 거리를 제공한다. 닫힌 접합부 자세와 별도 주행 구간 간격을 세 프리셋 모두 검증했다.

## 시점 검증과 설정

`createRaceViews.ts`에서 C는 `chase`와 `cockpit`을 전환하고, X는 주행만 → 트랙 PIP → 트랙 메인·주행 PIP를 순환한다. 콕핏에서는 유리를 숨기고 별도 재질의 계기판 밝기를 낮춘다. 노면 자세를 따르는 회전과 추가 조향 기울기를 분리하며 기본 `rollStrength`는 0.35, `shakeStrength`는 0.008이다. 움직임 줄이기 설정에서는 추가 기울기·부스트 흔들림을 끈다. 전체 뷰는 화면 비율에 맞춰 경로 전체를 담고 2.2px 경로선과 흰색·주황색 플레이어 표식을 표시한다.

Chrome 154의 실제 키 입력으로 W를 누른 채 C 전환 시 속도·시간·위치가 이어짐을 확인했다. 일시정지 상태 전환에서는 시간·위치가 유지되고 재시작은 시점과 난이도를 보존한다. 중급 콕핏 한 바퀴를 충돌·복귀 없이 주행했고 루프·스프링의 뒤집힌 자세를 확인했다. 빌드 미리보기 1440×900에서 Bloom 없이 콕핏·전체 뷰를 확인하고, 375×800 및 900×600에서 메뉴·시작 화면 겹침과 넘침을 보정했다. 사용자 회전 체감, Safari와 GPU 성능 측정은 남아 있다.

## 2단계 부스트 연출 검증

기본 성능은 일반 85m/s(306km/h), 부스트 1단계 125m/s(450km/h), 2단계 155m/s(558km/h)다. 완충 지속 시간 5초의 60%인 연속 3초부터 2단계로 전환한다. 카메라는 진입 순간 빠르게 후퇴하고 약 0.45초 동안 따라붙는다. 왜곡 패스는 Bloom 뒤·Output 앞에서 외곽에 적용하고 종료 시 약 0.6초 안에 비활성화한다. 빗금은 일반 주행에서 숨기며 부스트 1단계 4.6px, 2단계 6.6px 폭으로 그린다.

Chrome 자동 키 입력에서 충돌·복귀 없이 3.001초에 2단계로 진입하고 96m/s에 도달했다. 1440×900에서 일반 주행·해제 후 빗금 숨김, 해제 후 왜곡 패스 비활성화, 일시정지 초기화와 움직임 줄이기에서 왜곡·빗금 비활성화를 확인했다. 중앙은 기본 이미지 샘플 1회, 외곽은 최대 7회 샘플링하며 부스트 종료 후에는 패스를 건너뛴다. 실제 GPU 프레임 시간과 Safari 검증은 남아 있다.


## 고속 조향과 PIP 조정

조향 최대 각속도는 2.2rad/s다. 60m/s를 넘으면 속도의 제곱에 비례해 조향 여유가 줄어들며, 급한 코너를 최고 속도로 진입하면 높은 고도에서는 이탈 벌점을 받고 전진을 유지하며 낮은 고도에서는 경계 접촉으로 감속한다. `corneringReferenceSpeed`, `highSpeedSteeringLoss`, `maxYawRate`는 기체 성능 설정이고 장비 배율로 변경할 수 있다. 중급 트랙의 같은 급한 코너를 85m/s와 45m/s로 통과하는 테스트로 이탈과 정상 통과를 비교한다.

기체는 부스트 중 롤·피치·요 방향으로 진동하고 2단계에서 더 강해진다. `speedEffects.boostCraftShake`로 기체·장비별 강도를 조절한다. 움직임 줄이기에서는 진동을 끈다. 주행 장면은 Bloom·왜곡·OutputPass를 거치고 전체 트랙 장면은 별도 카메라와 OutputPass로 렌더링한다. 두 결과를 한 WebGL 캔버스에 합성하며 작은 화면은 PIP 크기의 해상도로 처리한다. PIP를 끄면 전체 트랙 장면을 렌더링하지 않는다.

키 바인딩 변경 UI·저장·기본값 복원은 후속 계획이며 현재 구현하지 않는다. 화살표 고도 조작은 노면 기준이다.

## 모바일 HUD와 웹앱 검증

v0.2.0: 상단은 속도·시간·코너 안내와 일시정지 버튼만 표시한다. 상세 정보·설정·설치·업데이트는 메뉴에 둔다. 왼쪽 원형 조이스틱은 좌우 아날로그 조향과 아래쪽 감속을 동시에 지원하며, 손가락 해제·취소·일시정지·화면 크기 변경 시 입력을 초기화한다. 오른쪽은 ㅏ 모양 고도·부스트 컨트롤이다. 고도선은 부스트 바로 왼쪽에 낮은 단계부터 위로 쌓인다. 현재 실제 고도는 굵은 청록색, 장애물 통과 고도는 주황색이다. 접근 시 필요한 ↑/↓ 키·버튼 횟수를 안내하고 안전 고도에 도달하면 안내를 지운다. 주행 PIP로 교환하면 고도·부스트와 짧은 충돌 안내도 그 뷰포트 안에 표시된다. 데스크톱도 자동 가속하며 S를 누르는 동안만 감속한다.

개발 서버는 서비스 워커를 등록하지 않는다. 설치·업데이트·오프라인 검증에는 `npm run build` 후 `npm run preview`를 사용한다. 버전·캐시·아이콘 관리는 [웹앱 안내](WEB_APP.md)에 기록했다.

주행 준비 메뉴는 난이도와 시작, 일시정지는 계속하기·재시작·난이도 변경을 중심으로 구성한다. Bloom·음향·진동은 설정 팝업에서 변경한다. C/X 미리보기에서는 큰 메뉴가 사라지고 하단 시점 도구만 남으며, Esc로 돌아가도 정지 상태를 유지한다. 모바일의 44px 진행·멈춤 버튼은 PIP 상단에 겹쳐 배치한다. 실제 고도 단계 변경에는 8ms 진동을 주며 경계 무효 입력에는 주지 않는다. 기존 진동 설정과 움직임 줄이기를 따른다.


## P3 타임어택 (v0.3.0)

격납고의 타임어택 또는 `/#drive`에서 난이도를 선택하고 시작한다. 3초 카운트다운 이후 정방향으로 체크포인트 24개를 순서대로 통과해 3랩을 완주한다. 상단에는 속도·현재 랩·총 경기 시간을 표시한다. 핫핑크 아크는 출발/결승선이고 다음 체크포인트는 밝은 아크다. 옆으로 벗어난 정방향 통과도 인정한다. 이탈은 강제 복귀 대신 감속과 5P 벌점을 주고 주행 안내·결과에 표시한다. 복귀 중 시간은 계속 흐르며 일시정지와 탭 이탈 중 시간은 멈춘다.

결과는 총 시간·각 랩 시간·최고 기록을 표시한다. R과 다시 도전은 카운트다운부터 새 경기로 시작한다. 기록은 트랙/난이도·규칙 버전·성능/고도 설정별로 저장하며 접근 차단 또는 손상 데이터가 있어도 경기와 재도전은 가능하다. `tests/timeAttack.test.mjs`는 순서·방향·고속 통과·복귀·3랩·시간·저장 실패와 실제 세 난이도 트랙을 검증한다.

설정의 **주행 효과음**과 **배경 음악**은 별도로 전환한다. 음악은 Web Audio로 합성하는 오리지널 Neon Circuit이며 외부 음원 다운로드가 없다. 시작·재개 등 사용자 입력 이후 오디오를 활성화한다. 일시정지 시 음량을 내려 멈추고 격납고로 나갈 때 AudioContext를 닫는다. 충돌 시 엔진만 약 0.65초 동안 출력이 떨어졌다 회복하며 음악 진행은 유지한다.


## v0.4.0 주행 판정 변경

코스 이탈 시 진행 거리·랩을 유지하고 감속하며 5P 벌점을 누적한다. 같은 이탈 구간에서는 중복 부과하지 않는다. 주행 안내와 결과에서 벌점을 확인하고, 재시작하면 초기화된다. 옆으로 벗어나도 정방향 체크포인트 통과는 인정하므로 필수 F 복귀 안내는 없다. 규칙 버전은 `time-attack-v3`로 변경해 기존 규칙 기록과 구분한다. 포인트 잔액과 완주 지급은 P6-A에서 연결한다.
