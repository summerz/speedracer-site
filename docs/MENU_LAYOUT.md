# 메뉴 화면 정보 구조 (격납고 · 캠페인 · 상점)

메뉴는 게임의 선택 순서를 그대로 따라 한 단계씩 깊어진다. 각 단계는 그 단계의 결정에 필요한 정보만 보여주고, 숫자는 문장 대신 시각 단위(별·핍·막대·델타·진행률)로 보여준다.

- 격납고(홈): 이어하기 · 진행 요약 · 내 기체
- 캠페인: 구역 → 트랙 → 상세(난이도 · 아이템 · 출전)
- 상점: 기체(성능 · 강화) / 아이템(구매)

## 화면 모드

| 모드 | 조건 | 원칙 |
|---|---|---|
| P · 세로 폰 | `(max-width: 760px) and (orientation: portrait)`, 폭 640px 미만 | 한 열. 주 행동 버튼은 하단 고정 바. |
| L · 가로 폰 | `(max-height: 500px) and (orientation: landscape)` | 헤더 한 줄. 목록은 가로로 흐르고(캐러셀 · 한 줄 카드), 상세는 좌우 두 칸. 레이싱 직전 화면이므로 회전 없이 출전까지 끝낸다. |
| D · 데스크톱/태블릿 | 그 외 | 격자 목록, 상세는 두 칸. 주 행동 버튼은 첫 화면에서 보인다. |

개발 환경에는 `사운드 관리` 탭과 플레이테스트 포인트(1,000,000 P)가, 운영 빌드에는 `이용 분석` 버튼이 추가된다. 두 경우 모두 헤더가 줄바꿈·겹침 없이 버텨야 한다.

## 공통 헤더

- P: 1행 워드마크 + 도구(음악·버전·설치), 2행 탭(균등 분할 세그먼트) + 잔액. 탭이 넘치면 가로 스크롤.
- 폭 430px 이하 세로 화면에서 `이용 분석` 버튼이 보이면 워드마크는 아이콘만 남긴다.
- L: 워드마크(캡션 숨김) · 탭 · 잔액 · 도구를 한 줄(약 60px)에.
- 화면 높이 계산에 헤더 높이를 하드코딩하지 않는다. 화면 루트가 `grid-template-rows: auto … minmax(0,1fr)`로 남는 높이를 나눈다.

## 격납고 (홈)

- 3D 기체 미리보기(P 위 · L/D 왼쪽) + 패널.
- 패널 순서: `이어하기` 카드(다음 코스로 바로 상세 열기) → `캠페인 ↗` → 진행 칩(`통과 n/32 · ★ a/96 · 보유 기체 m/5` + 상점 링크) → `내 기체`(보유 기체 썸네일 카드 · 성능 막대) → 추진 테스트 → `시험 주행 · NEON CIRCUIT`(포인트 획득 · 캠페인 기록 없음).
- 첫 실행(어느 모드에서도 통과한 코스가 없음): 카드가 `시작하기 · 캠페인 시작 ↗`로 바뀌고 캠페인 구역 화면으로 보낸다. 캠페인 배너도 `첫 코스 · 첫 도전`.

## 캠페인

모든 단계 상단: 경로(`캠페인 › 구역 › 트랙`, 앞 단계는 버튼) · 뒤로 버튼 · 모드 토글(`타임어택 n/32 | 경쟁 레이스 n/32`) · 출전 기체 링크.

목록 단계의 별은 세 난이도 중 최고 별점이다. 난이도는 상세에서 고르므로, 개요가 보이지 않는 선택에 좌우되지 않게 한다.

### 1. 구역

- `이어하기` 배너: 다음 도전 코스(`nextCampaignTrack`)의 구역 · 번호 · 이름과 바로가기. 모두 통과하면 완주 요약.
- 전체 진행: `통과 n/32` · `★ a/96` · 진행 막대.
- 구역 카드 8장: 구역색, 이름, 설명(P에서는 숨김), 트랙 4개 상태 점, `통과 n/4`, `★ a/12`, 상태(완주 ✓ / 진행 중 / 잠김). 다음 코스가 있는 구역은 `NEXT`. 잠긴 구역도 열어 볼 수 있다.
- P 2열 격자 · L 가로 캐러셀 · D 4×2 격자.

### 2. 트랙

- 구역 머리말: 이름, 설명, `통과 n/4`, `★ a/12`, 진행 막대.
- 트랙 카드 4장: 코스 썸네일, 번호, 이름, 지표 줄(랩 거리 · 고저차 · 장애물 · 랩 수), 랜드마크, `갈림길` 배지, 강도 6칸 핍, 고도 단수, (경쟁) 통과 순위, 최고 별, 통과 기록, 상태 칩(도전 / ✓ 통과 / 잠김), `NEW`. L에서는 지표를 한 줄로 줄이고 핍·랜드마크 줄을 생략한다.
- 썸네일은 상세의 3D 미리보기와 같은 렌더러·카메라로 찍은 이미지(`createTrackPreview().snapshot`)라 모양 · 각도 · 랜드마크가 상세와 일치한다. 트랙은 영역 중앙에 고른 여백으로 맞춘다. 트랙마다 한 번만 만들어 캐시하고, 카드를 먼저 그린 뒤 한 장씩 채운다. 잠긴 코스는 흐린 회색 + 🔒.
- P 1열 · L 한 줄 4장 · D 한 줄 4장(좁으면 2×2).

### 3. 상세 (위에서 아래 = 중요도 순)

1. 3D 미리보기, 제목 블록(`구역 · 번호`, 이름).
2. 스펙 타일: 강도 · 랩 거리 · 고저차 · 고도 · 장애물 · 랩 수.
3. 난이도 선택: 버튼마다 그 난이도의 별(`쉬움 ★★☆`).
4. 목표 카드: 통과 조건 + 랩/순위별 조건 대비 기록 표. 머리말에 난이도 설명.
5. 별 등급 사다리 ★ / ★★ / ★★★ + 감점 규칙 각주.
6. 갈림길(있을 때만), 특징 · 랜드마크 태그, 최단 완주 기록.

행동 영역: 아이템 장착(`아이템 n/2` 슬롯 + `변경` → 대화상자) · `도전하기` · 접근 상태. 아이템 장착은 출전 직전 결정이므로 여기서 한다. 모드가 이미 정해져 있어 타임어택에서는 경쟁 전용 아이템을 보여주지 않는다. 보유 0개면 상점 링크.

### 뒤로 가기

드릴인할 때 `history.pushState`로 기록을 남기고 `popstate`로 한 단계씩 돌아간다(안드로이드 뒤로 버튼 포함). Esc · 패드 B(`speedracer:menu-back`)도 같은 경로를 따른다. 경주에서 돌아오면 그 트랙 상세로 바로 연다.

## 상점

탭: `기체` / `아이템`. 강화는 기체에 속하므로 별도 탭이 아니다.

### 기체

- `기체 n종 · 보유 m` 머리말 + 기체 썸네일 카드(`src/craftCards.ts`: 렌더 이미지 · 이름 · 가격 / 보유 / 장착 중). P · L은 가로 스크롤, D는 한 줄. 격납고의 `내 기체`도 같은 카드를 쓴다.
- 큰 3D 미리보기 위에 이름 · 역할 · 상태 배지.
- 주 행동(구매 · 장착 · 판매)은 첫 화면에 보인다. P는 하단 고정 바.
- 하위 탭 `성능 | 강화`
  - 성능: 장착 기체 대비 막대 비교. 장착 기체는 흐린 막대, 표시 기체는 색 막대, 값과 델타(유리 `+` 청록, 불리 `−` 주황; `droneStats().fill` 기준). 부스트 · 제동력은 보조 수치 줄.
  - 강화: 업그레이드별 `이름 · 단계 핍(●●○) | 지표별 현재 → 다음 | 비용 버튼`. 미보유 기체는 최대 강화 시 수치를 미리 보여준다.

### 아이템

구매 전용 카탈로그: 이름, 설명, 가격, `보유 n / 한도`, 구매 버튼, 경쟁 전용 배지. 장착은 캠페인 상세에서 한다는 안내와 링크. 3D 미리보기는 숨기고, 카드는 `repeat(auto-fill, minmax(260px, 1fr))` 유동 격자에서 같은 줄끼리 높이를 맞추고 구매 버튼을 아래에 정렬한다.

## 키보드 · 게임패드 포커스

- 방향키 · 패드 십자키는 요소 가장자리 거리로 다음 대상을 고른다. 세로 이동은 가장 가까운 줄을 먼저 보고, 동점이면 중심이 가까운 쪽.
- 본문에서 위로 헤더에 닿으면 현재 GNB 탭(`aria-current`)으로, 헤더에서 아래로 내려오면 화면의 주 행동(`data-autofocus`)으로 간다.
- 화면 진입 시 `data-autofocus`에 포커스: 격납고 = 이어서 도전 / 캠페인 시작, 캠페인 구역 = 이어서 도전(없으면 첫 구역), 트랙 = 다음 도전 코스, 상세 = 도전하기, 상점 = 구매 · 장착(없으면 선택 기체 카드). 터치 전용 기기에서는 패드가 연결되지 않으면 진입 포커스를 생략한다.
- 선택 후 이동: 난이도 선택 → 도전하기, 격납고 기체 선택 → 이어서 도전.
- 레이스: 준비 → 레이스 시작, 일시정지 → 계속하기, 종료 → 통과 시 다음 트랙, 아니면 다시 도전. 포커스는 오버레이가 보인 뒤에 준다.

## 사운드 관리 (개발 전용)

같은 화면 규칙을 따른다: 100dvh 격자, 상단 세그먼트 탭, 같은 높이 카드 격자, 공용 버튼 · 배지, 두 칸이 각자 스크롤.

## 검증 뷰포트

390×844(P), 844×390(L), 1440×900(D)에서 개발 환경과 운영 빌드(`npm run build && npm run preview`)를 모두 확인한다.
