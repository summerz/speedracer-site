# 오디오 리소스

v0.16.3부터 레이스의 짧은 효과음은 Agent Audio MCP로 생성한 MP3를 사용한다. 엔진·바람·비의 연속음은 기존 Web Audio 합성을 유지한다. 음악은 제공 MP3를 로비/경주로 나누어 스트리밍 재생하며 [SOUNDTRACK.md](SOUNDTRACK.md)에 정리한다. 파일이 준비되지 않았거나 다운로드/디코딩이 실패하면 해당 이벤트를 기존 합성음으로 즉시 재생한다.

## 파일 및 출처

현재 파일은 `src/assets/audio/agent-audio/`에 있다. 16개 파일을 18개 이벤트에서 사용하며 총 137,058바이트(약 137KB)다.

생성은 설치된 Agent Audio 0.1.0의 MCP 서버에 독립 Python MCP SDK 클라이언트로 연결해 `audio_status`와 `generate_audio`를 호출했다. 모델은 Stable Audio 3 Medium의 공식 MLX 런타임이며 모델 리비전은 `da6edc54ddba10bfd79a077102ded687f80e882b`다. 사용자 대신 모델 라이선스를 수락하거나 인증·권한 제한을 우회하지 않았다. 생성 파일의 이용 조건을 기존 Kenney의 CC0 조건으로 간주하지 않는다.

3초 원본 WAV와 MCP 응답은 Git 제외 경로 `incoming-resources/agent-audio/race-sfx-v1/`부터 `race-sfx-v5/`에 보관한다. v2는 사용자 피드백에 따라 다시 생성한 출발·충전 완료·경계 이탈·고도 경고 2종·랩/마지막 랩 7개다. v3는 충전 완료·장애물 충돌·완주 3개를 다시 생성했다. v4는 부스트 성공·기체 충돌·장애물 충돌·상승 고도 경고 4개를 다시 생성했다. v5는 상승 경고만 맑은 고역 핑으로 다시 생성했다. [생성 스크립트](../scripts/generate-race-effects.py)는 각 큐의 원본 리비전을 지정하고 이미 있는 WAV를 재사용하며, 신규 생성에 실패하면 중단한다. `--cues`로 일부만 교체할 때 다른 파일과 manifest 항목은 유지한다. 재실행은 설치된 Agent Audio 전용 Python으로 한다.

```sh
~/.local/share/agent-audio/.venv/bin/python scripts/generate-race-effects.py
# 지정한 효과음만 다시 인코딩 (기존 WAV 재사용)
~/.local/share/agent-audio/.venv/bin/python scripts/generate-race-effects.py --cues start boost-full off-track warning-up warning-down lap final-lap
```

FFmpeg로 첫 유효 어택을 찾아 자르고, 보존 구간의 피크를 정규화한 뒤 3ms 어택·40ms 종료 페이드를 적용한다. 하강 고도 경고는 생성한 음색으로 130ms 펄스 두 개와 50ms 간격을 구성하고 두 번째 음을 낮춘다. 상승 경고는 현재 하강 경고 MP3의 두 음을 추출해 순서만 바꾼다. 음높이·음색·음량·각 음의 어택과 감쇠는 유지하고 낮은음 → 높은음으로 배치하며, 파형 자체를 역재생하지 않는다. 모노·44.1kHz·96kbps MP3로 압축하고 메타데이터를 제거한다. 디코딩 후 유한 샘플·무음·클리핑 검사를 통과한 파일만 교체한다. [manifest.json](../src/assets/audio/agent-audio/manifest.json)에 프롬프트 또는 파생 출처·원본/최종 SHA-256·길이·바이트·피크·RMS·편집 방법을 기록했다.

상승 경고만 다시 적용하려면 위 생성 명령의 옵션을 `--cues warning-up`으로 지정한다. 이 경우 모델을 호출하지 않고 하강 경고의 음 순서만 바꾼다. 참조한 하강 파일과 이전 상승 파일은 Git 제외 경로 `incoming-resources/agent-audio/race-sfx-v6/`에 해시별로 보관한다. 두 경고를 함께 생성할 때에도 하강 파일을 먼저 준비한 뒤 상승 파일을 만든다.

이전 v2의 충전 완료·현재 랩·마지막 랩은 생성한 단음 음색을 피치 변환해 각각 2·3·4개의 상승 음으로 구성한다. 랩은 장3도와 완전5도로 올라가고 마지막 랩은 옥타브까지 올라간다. 충전 완료는 240ms 음을 270ms 간격으로, 랩은 160ms 음을 180ms 간격으로 배치한다. 생성 결과의 멜로디를 짧게 잘라 쓰면서 방향이 사라지는 것을 피한다. v3 충전 완료는 고도 상승 경고와 구분하기 위해 피치 변환·두 음 편집을 없애고 단일 차임을 유지한다. 1.3kHz 이하를 줄여 밝은 잔향에 집중한다. 장애물 충돌은 500Hz 이하의 저음을 줄여 묵직한 충격을 억제한다. 완주는 단조 신스 화음을 목표로 생성하고 음량과 종료 페이드를 조정한다.

이전 Kenney 충돌·이탈 MP3와 CC0 라이선스는 저장소에 보존하지만 현재 카탈로그에서 사용하지 않는다.

## 준비와 재생

- `raceEffectFiles.ts`가 파일 URL과 재생 게인을 정의하고 `createRace.ts`가 오디오에 전달한다.
- 레이스 준비 화면에서 인코딩된 파일을 미리 받는다. 첫 사용자 입력으로 `AudioContext`를 활성화한 뒤 디코딩한다. 재시작·환경 변경에는 받은 바이트를 재사용하고, 새 컨텍스트에서 다시 디코딩한다.
- 이벤트 순간 준비된 버퍼를 즉시 재생하며 기존 합성음을 겹치지 않는다. 준비되지 않았으면 합성음을 사용한다. 비동기 로딩 완료 시 과거 이벤트를 재생하지 않는다.
- 충돌·경기 안내·고도 경고는 알림 버스로 보내고 엔진·비·음악을 잠시 낮춘다. 알림 길이는 실제 파일 길이를 따른다. 부스트 진입음은 배경 버스로 보내 경고음을 취소하지 않는다. 엔진 소스는 충돌 후에도 유지한다.
- 고도 경고는 방향을 바꾸거나 맞는 고도에 도달하면 즉시 취소한다. 반복 간격은 최소 0.8초다.
- 일시정지·효과음 끄기·레이스 해제 시 재생 소스를 중지한다. 해제 후 완료된 디코딩 결과는 보관하지 않는다. 실패한 다운로드/디코딩은 다음 활성화에서 재시도할 수 있다.

## 버전과 오프라인 캐시

앱 표시 버전과 리소스 버전은 역할을 구분한다. 표시 버전은 `package.json`에서 관리하고, 리소스는 내용 해시로 자동 관리한다.

1. MP3를 TypeScript에서 import하면 Vite가 내용 해시를 파일명에 붙인다. 작은 파일은 JavaScript 안에 인라인된다. 파일을 바꾸면 MP3 또는 포함한 JavaScript의 배포 URL도 바뀐다.
2. 빌드 플러그인이 모든 배포 파일의 SHA-256과 전체 리소스 세트의 세대 해시를 서비스 워커에 넣는다. MP3도 사전 캐시에 포함된다.
3. 새 서비스 워커는 이전 캐시에서 같은 URL의 파일을 찾아 SHA-256을 확인한다. 같은 내용이면 재사용하고, 없거나 변경/손상되었으면 다운로드한다. 고정 URL의 공개 리소스도 바이트를 검사한다.
4. 모든 파일 검증을 마친 뒤 새 버전이 업데이트 대기 상태가 된다. 사용자가 업데이트를 적용할 때 활성화한다. 설치 실패 시 현재 캐시를 유지한다.
5. 한 번 앱 준비가 완료된 뒤에는 네트워크가 없어도 캐시에서 효과음을 준비한다. 아직 이전 버전을 실행하는 다른 탭에는 이전 해시 파일을 제공한다.

파일을 교체할 때 별도 수동 리소스 버전 번호는 필요 없다. `src/assets/audio/`의 파일과 카탈로그를 수정하고 빌드하면 URL·SHA-256·세대 해시가 함께 갱신된다. 새 효과음을 추가할 때는 출처/라이선스, 재생 게인, 합성 fallback, 정지/해제 동작을 함께 기록한다.

## v0.16.3 검증

전체 자동 테스트 315개·타입 검사·프로덕션 빌드를 통과했다. Chromium의 실제 Web Audio에서 18개 이벤트 슬롯 디코딩, 파일 재생, 방향 경고 취소, 일시정지·음소거·해제를 검증했다. 빌드된 서비스 워커에 16개 파일의 바이트가 포함되는 것도 검사했다. `height`·`countdown`은 사전 캐시되는 JavaScript에 인라인되어 있다.

브라우저 검사는 물리 출력을 음소거한 상태로 진행했다. 직접 청취와 실제 iPhone의 음악·엔진 혼합 시 구분감/음량 검증은 남아 있다. 검사 기록은 Git 제외 경로 `output/playwright/agent-audio-browser-report.txt`에 있다.

## v0.16.5 충전·장애물·완주 재조정

Agent Audio MCP로 3개를 새 원본 경로에 다시 생성했다. 충전 완료는 고도 상승 경고의 두 음과 구분하도록 단일 차임으로 구성한다. 장애물 충돌은 금속 파손·저음 충격 대신 짧은 전기 스냅과 방전을 목표로 생성하고 저음을 제거한다. 완주는 과한 팡파르 대신 단조 신스 화음을 목표로 생성하고 게인을 0.32로 낮춘다.

관련 자동 테스트 32개·타입 검사·빌드, 전체 16개 파일의 해시와 PWA 캐시를 검증했다. Chromium 실제 Web Audio에서 18개 슬롯의 디코딩·단일 파일 재생·경고 방향 전환/취소·일시정지·음소거·해제를 통과했다. 기록은 `output/playwright/agent-audio-browser-report-v3.txt`에 있다. 물리 출력은 음소거했으며 직접 청취·음색 적합성·실제 iPhone 혼합 음량은 미검증이다.

## v0.16.6 부스트 성공·충돌·상승 경고 조정

Agent Audio MCP로 4개 원본을 새 리비전에 생성했다. 부스트 성공은 생성한 밝은 신스 플럭으로 120ms 간격의 장3도·옥타브 상승 3음을 구성한다. 상승 경고는 맑은 고역 핑의 장3도 상승 두 음으로 구성한다. v5에서 1100–10000Hz 대역을 사용해 낮고 둔탁한 성분을 줄였다. 두 안내는 음색·길이·음 개수·리듬을 다르게 구성한다.

기체 충돌은 자기장 접촉·에너지 울림, 전기선 충돌은 짧은 전자 방전을 목표로 생성한다. 450Hz/700Hz 이하를 줄인 뒤 필터링한 구간의 피크로 게인을 맞추고 각각 0.52로 재생한다. 직접 청취·음색 적합성·실제 iPhone 혼합 음량 확인은 남아 있다.


## 개발용 사운드 관리 및 라이브러리

`npm run dev`에서 격납고·캠페인·상점의 공통 상단 내비게이션에 있는 상점 오른쪽 **사운드 관리** 버튼으로 들어간다. **게임에 지정** 주소는 `http://127.0.0.1:5678/#sound-lab?view=assignments`, **라이브러리** 주소는 `http://127.0.0.1:5678/#sound-lab?view=library`이다. 탭 전환은 주소와 브라우저 방문 기록에 반영되어 새로고침·뒤로 가기에도 선택한 화면이 열린다. `#sound-lab`은 게임에 지정 화면을 연다. 배포 빌드에는 페이지·버튼·개발 전용 저장 코드가 포함되지 않는다.

- **게임에 지정**: 18개 효과음 이벤트와 로비 1곡·경주 8곡을 선택해 현재/원본/후보를 재생한다. 효과음 음량을 조정하고 라이브러리 파일로 교체한다.
- 교체 후보는 펼쳐진 파일 목록으로 표시한다. 후보를 누르면 바로 재생하고 선택 상태만 바꾸며, **이 사운드로 교체**를 눌렀을 때 적용한다. 연속으로 후보를 눌러도 목록의 스크롤과 키보드 포커스를 유지한다.
- **라이브러리**: 효과음/배경음악을 따로 보관하고 여러 파일을 한 번에 추가한다. 출처는 업로드 또는 에이전트 생성으로 표시한다. Agent Audio가 생성한 WAV도 이곳에 추가할 수 있다.
- 목록은 파일명을 먼저 표시하고 제목과 현재 사용처를 함께 보여준다. 지정되지 않은 파일은 미사용으로 표시한다. 목록을 누르면 해당 파일을 재생하며, 목록 상단의 **미리듣기 켜짐/꺼짐**으로 자동 재생을 끈다. 끄는 즉시 현재 재생도 정지한다. 수동 미리 듣기는 계속 사용할 수 있다.
- 라이브러리의 **사용할 곳**도 펼쳐진 목록으로 표시하고 각 사용처의 현재 파일명을 함께 보여준다. 선택하면 현재 지정된 소리가 바로 재생되며, 미리듣기를 끄면 자동 재생하지 않는다. 현재 사용 파일과 수동 비교 재생 버튼도 제공한다. 파일 목록과 사용처 목록은 연속 선택 시 스크롤과 키보드 포커스를 유지한다. 후보를 들어본 뒤 **선택한 곳에 지정**한다. 로비는 한 곡, 경주 음악은 **사운드트랙 #1, #2…**로 구분한다. 음악별 **사운드트랙에 추가/사운드트랙에서 제외**로 경주 재생 목록을 편집하며, 제외한 파일도 보관한다. 경주 곡이 없으면 경주 중 음악만 무음으로 둔다.
- 효과음은 각 3초·8MB 이하, 음악은 각 20분·32MB 이하로 제한한다. MP3/WAV/OGG/M4A/FLAC 중 브라우저가 해석할 수 있는 파일을 받는다. 효과음은 유한 샘플·무음 검사를 거친다.
- 파일·지정 정보는 현재 브라우저/주소의 IndexedDB에 저장된다. 다른 파일을 지정하거나 원본으로 복원해도 이전 후보는 남는다. 파일명 바로 아래의 **파일명 변경 / 파일 삭제** 버튼으로 업로드·에이전트 파일을 관리한다. 이름 변경은 확장자를 유지하고 중복 이름·경로 문자를 거부하며, 같은 파일 ID를 유지해 사용처·재생·게임 지정이 바뀌지 않는다. 변경한 이름은 브라우저 저장과 내보내기에 반영된다. 삭제는 별도 확인을 거치며 사용 중인 이벤트를 알려준다. 기본 이벤트는 원본으로 되돌리고 추가 사운드트랙은 제거한다. 프로젝트 원본은 복구용으로 보관해 이름 변경·삭제를 지원하지 않으며, 브라우저 파일명 변경은 디스크 원본의 이름을 변경하지 않는다.
- 변경은 다음 주행부터 적용된다. 관리 페이지에서는 로비 음악을 정지하고 선택한 파일 하나만 시험 재생한다. 페이지 이동·백그라운드 전환 때 시험 재생을 멈춘다. 엔진·바람·비 같은 연속 합성음은 별도 코드로 관리한다.

**라이브러리·변경분 내보내기**는 미사용 파일까지 포함한 JSON 백업을 저장한다. **보관함 가져오기**는 백업의 파일들을 다시 추가하며 기존 파일과 게임 지정을 유지한다. 반복해서 가져오면 후보가 중복될 수 있다. 브라우저 데이터 삭제 전에는 반드시 내보낸다. 브라우저 보관함은 디스크 폴더와 자동 동기화되지 않는다.

**게임에 지정 / 라이브러리** 버튼 줄 오른쪽에는 프로젝트 반영 안내를 표시한다. 브라우저에 지정·음량·사운드트랙 포함 여부 변경 또는 업로드·에이전트 파일이 있으면, 내보내기 후 프로젝트 폴더의 터미널에서 실행할 `npm run audio:import -- ~/Downloads/speedracer-audio.json` 명령을 보여준다. 다운로드 경로가 다르면 수정해야 하며, 다른 이용자에게 적용하려면 프로젝트 반영 후 배포해야 한다. 모바일에서는 안내가 버튼 아래로 내려간다. 새로고침 후 저장된 변경도 확인해 표시하며, 터미널 명령의 실행 여부를 자동으로 판별하지 않으므로 브라우저 변경이 남아 있는 동안 안내를 유지한다.

선택을 프로젝트 및 배포 파일에 반영할 때:

```sh
npm run audio:import -- /경로/speedracer-audio.json --dry-run
npm run audio:import -- /경로/speedracer-audio.json
npm run build
```

반영 도구는 모든 변경 파일을 먼저 검사·인코딩하고 나서 기존 파일을 교체한다. 효과음은 모노 96kbps, 음악은 스테레오 64kbps MP3로 압축한다. 효과음 음량은 `src/assets/audio/effect-levels.json`, 효과음 파일 출처·해시는 manifest에 기록한다. 음악 재생 목록은 `src/assets/audio/music-playlist.json`에 저장하며 첫 곡은 로비, 이후 곡들은 경주 목록이다. 새로 채택한 음악도 압축 파일과 함께 반영하며 제외한 기존 원본은 삭제하지 않는다. 음악의 지정 정보와 원본은 JSON 보관함에 남고 배포 해시는 빌드에서 생성한다. 복귀/고도 변경과 반 랩/랩은 각각 파일을 공유하므로 서로 다른 파일 지정은 반영 전에 충돌로 보고한다. 실패한 쓰기는 이전 파일로 복원한다.

전체 JSON 보관함·교체 전 파일은 Git 제외 경로 `incoming-resources/audio-library/<백업 해시>/`에 남긴다. **후보·생성 원본·미사용 파일은 Git에서 제외하고, 채택된 압축 파일·설정·출처 정보만 추적한다.** 이 폴더는 별도 백업이 필요하다. 다음 빌드는 최종 바이트의 SHA-256과 새 캐시 세대를 생성하므로 같은 이름으로 교체한 음악도 이용자의 업데이트에 포함된다.
